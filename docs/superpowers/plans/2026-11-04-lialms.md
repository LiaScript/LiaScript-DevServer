# LiaLMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the product to LiaLMS, rebuild the gateway's admin page as a HUD dashboard (dark and light),
make the student login personal with a role transition, and let the chat shell switch between course and chat
on phones.

**Architecture:** Server-rendered HTML strings in `src/gateway.ts` (admin page) and a new `src/login.ts` (the
front's login and welcome pages, pure functions), styled by `views/admin/admin.css` under the strict CSP. The
phone mode is a new browser script `views/phone.js` next to `chat.js`, fed by a `lia:shell` DOM event that
`chat.js` dispatches; its pure helpers are tested in a `vm` like `views/teachers.js`.

**Tech Stack:** TypeScript (parcel bundle, `tsc` for `lib.ts`), Express (DevServer), plain `http` (gateway),
vanilla browser JS, `src/check.js` (node `assert`, runs the BUILT `dist/index.js`: `npm run build` first).

**Spec:** `docs/superpowers/specs/2026-11-04-lialms-design.md`. Mockups: Design canvas
https://claude.ai/artifact/2EKTZjhDuFoo1Mfix3F3GB (artboards "A · Umschalten", "Dashboard", "Login · Lernende",
"Login · Autor").

## Global Constraints

- Visible name `LiaLMS`; npm package, CLI names, `views/layouts/index.hbs` and code identifiers stay.
- Admin page CSP stays: `script-src 'self'`, `style-src 'self'`; the HTML must match none of
  `/<script>|\son\w+="|\sstyle="/` (check.js). Every new static file goes into `STATIC` (gateway.ts:242).
- The front (login) sends no CSP; inline `<style>` and one inline `<script>` are allowed there.
- Every name or message text from a user goes through `esc()`.
- The login success page keeps `sessionStorage.setItem('lia-share-token', "<token>")` verbatim, and no other
  quoted 32-hex string may come before it (check.js reads the first one).
- Shell layout CSS lives in the inline `<style>` of `views/chat.html` (chat.css is also loaded in the messages'
  iframe). `gotoScript` untouched.
- Phone breakpoint = the existing `WIDE` = 768 px (`max-width: 767px`).
- Texts: English keys, German in `TEXTS.de` (shell) or `de`/`en` objects (admin, login); German when there is
  no `Accept-Language`.
- Colors exactly as in the spec, section 2 (dark and light) and section 3 (`#147375`, `#4c3bb8`, `#f5f4fb`).
- Fonts: Geist (shipped) and Geist Mono (new, OFL, `views/admin/geist-mono.woff2`).

## Review Focus

1. A `?user=` name with HTML or a very long name on the login: shown escaped, greeting wraps instead of
   overflowing the card. (Task 5 tests the escaping.)
2. The newest `@all` message on the login before auth holds HTML or is 2000 characters long: escaped and cut to
   200 characters with `…`. (Task 5.)
3. Replayed history when the chat shell (re)connects must not count as unread on the phone, nor switch views.
   (Task 7, `Phone.unread()` test.)
4. The admin poll replaces `#rows` every 5 s: an active filter chip or search must stay applied to the new rows.
   (Task 4, manual step in the browser.)
5. Turning a tablet across 768 px or rotating a phone: leaving phone mode restores float/dock exactly as before,
   entering it shows the course. (Task 7, manual step.)
